01 / START HERE

The ingredients of learning

Before attention, start with the distinction that makes everything else click: the model’s parameters are learned; its activations are computed.

PARAMETERS

The learned recipe

Weights and biases are numbers stored in the model. Training adjusts them to make useful predictions.

ACTIVATIONS

The current calculation

Embeddings, hidden states, Q, K, and V are the values produced while processing a particular input.

OBJECTIVE

The learning signal

A loss measures how well the output matches the training target. Gradients connect that error to the parameters.

What is a neural network?

A neural network is a sequence of parameterized calculations. A linear layer mixes input features using a weight matrix and often a bias. A nonlinear activation then lets the network represent relationships that a single linear map cannot.

h = activation(xW + b)

This guide uses row vectors: an input x multiplies W on the right. Dimensions must agree.

  1. Input x
  2. Linear map xW + b
  3. Nonlinearity
  4. Hidden representation h
  5. Prediction

For example, a neuron receives x = [2, 1], uses weights [0.5, −1] and bias 0.2. Its pre-activation is 2 × 0.5 − 1 + 0.2 = 0.2. ReLU keeps the positive value: max(0, 0.2) = 0.2. Changing the input changes this result immediately; changing the weights requires an update.

“Is [1, 0] a weight?”

In our example, xanimal = [1, 0] is the token’s representation. It is an activation. The matrix that transforms it is a parameter. The embedding table itself is learned, but the selected vector used in a forward pass is an activation.

How learning happens

  1. Training examples
  2. Forward pass
  3. Prediction + target
  4. Loss
  5. Backpropagation
  6. Optimizer update

Backpropagation applies the chain rule to calculate how each parameter affects the loss. The optimizer uses those gradients to update parameters. They are distinct steps: calculating a direction is different from taking a step.

wnew = wold − η · ∂L/∂w

Basic gradient descent. η is the learning rate. Adam and AdamW also use running statistics; AdamW applies decoupled weight decay.

If w = 0.50, ∂L/∂w = −0.20, and η = 0.10, the new value is 0.50 − 0.10 × (−0.20) = 0.52. A negative gradient means a small increase in this parameter locally decreases the loss. An overly large step can overshoot.

Data is essential, but it is not the only ingredient

Useful behavior depends on data quality and diversity, model capacity, architecture, objective, and optimization. More data alone does not guarantee better reasoning. Held-out evaluation checks whether the model generalizes.

02 / REPRESENTATION

From text to vectors

A Transformer reads arrays of numbers. Tokenization determines the units; embeddings give each unit a learned starting representation.

  1. Text
  2. Tokenizer
  3. Token IDs
  4. Embedding lookup
  5. Position information
  6. Hidden states X

A token is not always a word

A tokenizer maps text into a sequence of discrete vocabulary entries. Tokens can represent whole words, word pieces, punctuation, whitespace, or byte-based units. The exact split depends on the tokenizer.

The animal was very

Illustrative tokens only. These boundaries and the numbers below are not from a particular tokenizer.

Suppose these tokens map to IDs [17, 302, 41, 98]. ID 302 is an index, not a measurement: “animal” is not numerically more meaningful than token 17. An embedding lookup selects rows from a learned table.

The embedding table

E ∈ ℝvocab_size × d_model  X = E[token_ids]

For n tokens, X has shape n × d_model. The batch dimension is omitted in this guide.

If the table has 50,000 tokens and a representation width of 768, each input token selects one 768-number vector. Those coordinates are learned features; they generally do not have neat human labels like “animalness” or “tiredness.” Similar uses can lead to useful geometric relationships, but that is an outcome of training.

Embedding vs. hidden state

An embedding is the starting token representation. After a block mixes context and transforms features, its output is a new hidden state. Later layers project that updated hidden state into Q, K, and V.

How does the model know the order?

Without positional information, basic self-attention treats tokens as a set: reordering the rows simply reorders its output. Word order matters, so models incorporate positions.

ADDITIVE POSITIONS

Add a position vector

The original Transformer adds sinusoidal position encodings to token embeddings. Learned positional embeddings are another choice.

ROTARY POSITIONS

Rotate queries and keys

RoPE applies position-dependent rotations to Q and K so their dot products encode relative-position information. It is not simply an extra vector added to X.

X0 = E[token_ids] + P

This is the additive-position version. Positional schemes vary between architectures.

“The dog chased the cat” and “The cat chased the dog” contain the same words but describe different events. Position information and the model’s learned transformations help keep those relationships distinct.

Why the same token can mean different things

“Bank” starts with the same lookup vector in “river bank” and “bank loan,” assuming the same token ID. Attention brings in different surrounding information, so the contextual hidden states diverge. The embedding table does not need a separate entry for every possible sentence.

  1. Same token embedding
  2. Different surrounding tokens
  3. Different attention outputs
  4. Different contextual hidden states

Reveal explanation

An embedding lookup supplies a learned starting vector. Transformer attention makes that representation depend on the surrounding context; positional information helps distinguish order.

Attention is one part of the block

Attention moves information between positions. The feed-forward network transforms features at each position. Residual paths and normalization make deep stacks easier to optimize.

Multi-head attention and Wₒ

In ordinary multi-head attention, each head has its own learned projections. All heads read the same input hidden states, but can extract and combine different features.

Head 1
Q₁ · K₁ᵀ → weights → V₁
Head 2
Q₂ · K₂ᵀ → weights → V₂
Head 3
Q₃ · K₃ᵀ → weights → V₃
  1. Concatenate head outputs
  2. Learned output projection Wₒ
  3. One attention output
MultiHead(X) = Concat(head₁, …, headh)WO

Wₒ mixes the combined head features and returns them to the model width.

With width 768 and 12 equal heads, a typical head width is 64. Each head returns n × 64; concatenation gives n × 768. Heads can learn different patterns, but a head is not guaranteed to have one clean grammatical job. Grouped-query and multi-query attention share key/value projections across some query heads.

Encoder, decoder, and cross-attention

ArchitectureAttention patternTypical objective or use
Encoder-only, e.g. BERTBidirectional self-attention across visible input tokensMasked-token prediction and representations
Decoder-only, GPT-styleCausal self-attention over the current token and its prefixAutoregressive next-token prediction

In self-attention, Q, K, and V come from the same sequence of hidden states. In cross-attention, Q comes from the receiving sequence while K and V come from another sequence, such as encoder outputs. ACT uses this idea to read observation features into action positions.

“Decoder” has more than one meaning

A Transformer decoder is an attention-based stack. An autoencoder decoder reconstructs or generates data from a latent representation. A component can satisfy both descriptions, but the terms are not interchangeable.

04 / ATTENTION, UNPACKED

Who reads what, and how much?

Q and K determine the mixing weights. V supplies the content being mixed. All three projections learn through the model’s final prediction loss.

Q · QUERY

What am I looking for?

A learned projection of the receiving token’s current representation.

K · KEY

How can I be matched?

A learned projection used for comparing a source token with a query.

V · VALUE

What information do I send?

A learned projection containing the features that will be mixed into the output.

One input, three learned projections

Q = XWQ  K = XWK  V = XWV

Projection biases are omitted for clarity. These matrices are optimized jointly with the rest of the model, not trained as separate supervised tasks.

The request / match / content language is an analogy. The model uses vectors and arithmetic, not literal questions or database addresses. Every token can produce all three vectors. The same matrix within a head and layer is applied to each token; there is not a different WQ for each word.

  1. Hidden states X
  2. Q and K → dot products
  3. Scale and mask
  4. Row-wise softmax
  5. Mix V
  6. Attention output
A = softmax((QKᵀ / √dk) + M)
Attention(Q, K, V) = AV

Softmax is applied separately to each query row. A causal mask M is 0 for allowed positions and −∞ for future positions.

Keep the dimensions straight

The scaling by √dk keeps dot-product magnitudes from growing with feature dimension under typical variance assumptions. Without scaling, softmax can become too concentrated and its gradients small. Larger scores mean larger relative weights, not a guaranteed explanation of the model’s reasoning.

Try it: scores become a mixture

These are three already scaled, unmasked scores for one query. Move a score and watch the attention weights and weighted value vector change. The values are fixed for this demonstration.

0.665 × [10, 0] + 0.245 × [0, 6] + 0.090 × [1, 1] ≈ [6.742, 1.558]

Softmax uses exp(sᵢ) / Σⱼ exp(sⱼ). Scores [2, 1, 0] become about [66.5%, 24.5%, 9.0%]. The weights sum to 1; the values can contain positive or negative numbers. This softmax is over source positions, not vocabulary entries.

The output is a representation, not a word

In a real Transformer, attention is followed by output projection, residual paths, an MLP, other blocks, and a final vocabulary projection. For the next calculation only, we pretend the two output coordinates are logits for “tired” and “street.”

How the value projection actually learns

Apply a second softmax, now over the toy vocabulary [tired, street]. From logits [0.3302, 0.6698], we obtain P(tired) ≈ 0.4159. If the target is “tired,” the cross-entropy is −ln(0.4159) ≈ 0.8773.

∂L/∂logits = prediction − one_hot(target)
≈ [0.4159, 0.5841] − [1, 0] = [−0.5841, 0.5841]

Because the output is a weighted sum of values, each value receives this gradient multiplied by its attention weight. The gradient continues through V = XWV into WV. No one supplies a “correct value vector.” The next-token target supervises the entire differentiable computation.

Attention weights are not model weights

Attention weights A are computed activations. WQ, WK, and WV are learned parameters. K and V may be cached during generation, but caching activations does not turn them into parameters.

05 / THE COMPLETE LOOP

From hidden states to the next token

Training adjusts the model. Inference uses it. Both run forward computations, but they differ in their targets, updates, and execution pattern.

Trace one prediction from start to finish

  1. “The animal was very”
  2. Token IDs
  3. Embeddings + positions
  4. Transformer blocks
  5. Final normalization
  6. Vocabulary logits
  7. Probabilities
  8. Next token

After the last block, the hidden state at the final input position is mapped to a score for every vocabulary entry. These scores are logits, which can be any real numbers. Softmax converts them into a probability distribution.

logits = hfinalWvocab + b
P(next token = i) = exp(logitᵢ) / Σⱼ exp(logitⱼ)

The vocabulary projection is often tied to the embedding table. The output bias and exact normalization depend on the architecture.

An illustrative distribution might assign “tired” 68%, “hungry” 12%, “large” 4%, and all other tokens 16% together. These numbers illustrate the mechanism; they are not measured outputs from a real model. The selected token is appended to the context and the process repeats.

The input sequence and target sequence are shifted by one position. Teacher forcing means the model receives the actual preceding training tokens rather than its own sampled outputs. The causal mask prevents later tokens from leaking into earlier predictions.

L = −(1/N) Σt log P(targett | prefixt)

Average over N valid target positions; padding and other excluded positions should not contribute.

If the correct token gets probability 0.68, its loss is −ln(0.68) ≈ 0.386. If it gets 0.02, the loss is 3.912. This objective rewards assigning probability to the observed target. It does not directly measure truth or reasoning quality.

The full backward path

  1. Cross-entropy loss
  2. Vocabulary projection
  3. Transformer blocks
  4. Attention + MLP gradients
  5. Embedding gradients
  6. Optimizer update

Autodifferentiation records how the forward computation depends on trainable parameters and applies the chain rule in reverse. WQ and WK receive gradients through the score calculation; WV receives gradients through the value mixture. Wₒ, the MLP, normalization parameters, the vocabulary head, and the embedding table also receive gradients if trainable.

Learning a relationship is indirect

Nobody has to annotate “this pronoun must attend to this noun.” A pattern can emerge if using it repeatedly improves the objective. Attention maps alone are not a complete or necessarily faithful explanation of the final prediction.

What changes at inference?

TRAINING

Compute, compare, update

Known targets → loss → backpropagation → optimizer steps. Many target positions can be trained together.

INFERENCE

Compute, select, append

Parameters normally stay fixed. Prompt processing is followed by sequential next-token generation.

Prefill processes the prompt and creates the initial cache. Decode processes each newly generated token. Sampling controls which token is selected: greedy decoding picks the highest logit; temperature rescales logits; top-k or top-p can restrict the sampling set. Lower temperature generally concentrates the distribution. These controls do not retrain the model.

Why cache keys and values?

In a causal Transformer, earlier tokens cannot see later tokens. Their per-layer K and V activations remain usable as the sequence grows. A KV cache saves those tensors, so decoding only needs new projections for the new token and attention over the accumulated keys and values.

  1. Cached K, V for the prefix
  2. New token → new Q, K, V
  3. Append new K, V
  4. New Q attends over the cache
  5. New hidden state

Previous queries are generally not needed: the current step needs the new query. Caching avoids repeated prefix work; it does not eliminate attention over the growing context or make generation parallel across unknown future tokens.

KV memory ≈ 2 × B × L × n × hKV × dhead × bytes_per_element

2 for K and V; B = batch size, L = layers, n = cached sequence length. This simplified estimate assumes equal K/V head dimensions and a full cache.

For B = 1, L = 32, n = 4,096, hKV = 32, dhead = 128, and 2-byte storage, that is about 2 GiB for K and V alone. Grouped-query attention with 8 KV heads would use about 0.5 GiB under these assumptions. Actual systems may quantize, share, page, or limit the cache.

A conversation is not usually an optimizer step

The model can adapt its responses to information in the context without changing its parameters. Context, cached activations, and long-term learned parameters are different forms of state.

06 / COMPRESSION & RECONSTRUCTION

Learn a representation by reconstructing

An autoencoder learns to turn an input into a latent representation and reconstruct the input from it. A useful constraint prevents it from merely copying.

  1. Input x
  2. Encoder f
  3. Latent z
  4. Decoder g
  5. Reconstruction x̂

Why encode and decode?

The encoder learns a representation that preserves useful structure. The decoder forces that representation to contain enough information to reconstruct the target. A smaller bottleneck is one constraint; sparse, denoising, or other regularized autoencoders can use different constraints, including latents that are not lower-dimensional.

z = fθ(x)  x̂ = gφ(z)
Lreconstruction = (1/D) Σᵢ (xᵢ − x̂ᵢ)²

Mean squared error is one choice for continuous data. Reconstruction losses should fit the output model and task.

Worked example: 784 pixels → 32 numbers

A 28 × 28 grayscale image has 784 pixel values. An undercomplete encoder might map those values to a 32-dimensional latent vector. A decoder maps the 32 numbers back to 784 predicted pixel values.

784input dimensions
→
32latent dimensions
→
784output dimensions

The latent need not store pixels literally. It may encode shared features that help reconstruct many examples. To turn this into a practical compression format, you also need considerations such as quantization, coding, and storage overhead; fewer latent dimensions alone is not a complete codec.

What can you use it for?

DENOISING

Recover a clean target

Feed a corrupted sample to the encoder and compare the reconstruction with the clean original.

REPRESENTATION LEARNING

Keep useful features

Train the encoder and decoder, then use the latent as input to another task or model.

ANOMALY DETECTION

Measure reconstruction error

A model trained on normal data may reconstruct unusual data poorly. Calibrate thresholds on held-out examples.

Autoencoders can also support dimensionality reduction and learned compression. Unlike linear PCA, a neural encoder can learn nonlinear relationships. However, a highly expressive model may reconstruct anomalies well too; reconstruction error is evidence to evaluate, not proof that an example is abnormal.

Why not just sample a random latent?

Reconstruction training does not require the decoder to behave sensibly everywhere in latent space. Training examples might occupy separated regions, while arbitrary latent points fall into areas the decoder never learned to use.

Ordinary autoencoder

Good reconstructions do not imply a known distribution to sample from.

VAE objective

A probabilistic model adds a prior and a regularization objective.

Conceptual sketch, not measured latent geometry. A VAE encourages structure; it does not guarantee perfect coverage or interpretable axes.

Reconstructing is not the same objective as predicting the next token

A GPT-style model does not require one compressed latent bottleneck between an encoder and decoder. BERT’s masked reconstruction objective is sometimes called “autoencoding,” but its architecture is not the classical bottleneck autoencoder.

07 / PROBABILISTIC LATENTS

A latent distribution, not just a point

A variational autoencoder learns an approximate posterior over latent variables, then uses samples from it to reconstruct. A prior gives us a distribution for generation.

  1. Input x
  2. Encoder
  3. μ and log σ²
  4. Sample z = μ + σ ⊙ ε
  5. Decoder
  6. Reconstruction

Prior vs. approximate posterior

PRIOR p(z)

Before seeing an example

A common choice is N(0, I), a standard normal distribution over latent variables. It provides a distribution to sample at generation time.

APPROXIMATE POSTERIOR qφ(z|x)

After seeing this example

The encoder predicts parameters such as μ(x) and σ(x) for an input-dependent latent distribution.

p(z) = N(0, I)
qφ(z | x) = N(μ(x), diag(σ²(x)))

This is the common diagonal-Gaussian case. μ and σ are vectors; σ must be positive.

The true posterior p(z | x) is generally hard to compute. The encoder learns qφ(z | x) as an approximation. The decoder defines a conditional output distribution pθ(x | z), often summarized visually by its mean reconstruction.

μ and σ are outputs, not the encoder’s stored weights

The encoder’s parameters are learned. A particular input produces particular μ and σ activations, just as a token representation produces particular Q, K, and V.

How can randomness participate in backpropagation?

ε ∼ N(0, I)  z = μ + σ ⊙ ε
σ = exp(0.5 × log_variance)

⊙ is element-wise multiplication. Implementations often predict log variance for unconstrained numerical outputs.

We draw ε independently and transform it with differentiable operations. For a fixed random draw, z changes smoothly with μ and σ, so gradients can flow through the decoder back into the encoder. Sampling has not vanished; its dependence on the trainable parameters has been expressed in a differentiable form.

Try one latent coordinate

z = 1.0 + 0.5 × (−0.4) = 0.80

The slider chooses a fixed illustrative noise value. Real training draws ε from the normal distribution.

Two pressures in one objective

L = Eqφ(z|x)[−log pθ(x | z)] + β · KL(qφ(z | x) || p(z))

With β = 1, this is the negative evidence lower bound (ELBO). Training commonly estimates the expectation with sampled z.

TermWhat it encouragesPotential tension
Reconstruction / negative log-likelihoodKeep information needed to explain the input.Can favor using latent information very specifically.
KL divergenceKeep the inferred latent distribution close to the prior.Can discourage carrying information about the input.

The KL term measures a difference between distributions; it is not a distance between two sampled points and it is not symmetric. A larger β increases regularization pressure, potentially sacrificing reconstruction. Results depend on architecture, decoder likelihood, and training—not a universal rule that every VAE must be blurry.

The closed-form Gaussian KL and a numerical example
KL = ½ Σⱼ (μⱼ² + σⱼ² − 1 − log σⱼ²)

For a diagonal Gaussian posterior and a standard normal prior.

For one dimension with μ = 1 and σ = 0.5: KL = 0.5 × (1 + 0.25 − 1 − ln(0.25)) ≈ 0.818. If μ = 0 and σ = 1, q equals the prior and this KL is 0.

Regularization is an incentive, not a guarantee

VAEs encourage a useful latent distribution, but do not automatically yield disentangled concepts, perfect interpolation, or meaningful samples at every point. A powerful decoder can ignore z, a failure mode called posterior collapse.

Generation and interpolation

  1. Sample z from p(z)
  2. Run the trained decoder
  3. Produce a new output

Generation can bypass the encoder because the prior supplies z. Reconstruction instead uses a latent inferred from a particular x. Interpolation uses z(t) = (1 − t)z₁ + tz₂ and decodes the intermediate points; the quality of that path is something to inspect, not assume.

VAEs have been used for images, audio, molecules, and other structured data. In some latent diffusion systems, a VAE-like image encoder/decoder serves as a learned codec around a separate generative process. That does not make the language model in the same system a VAE.

The conditional VAE bridge to ACT

A conditional VAE models an output x given context c. Its encoder can use both the target and the context during training; its decoder receives z and the context. For ACT, the target is a demonstrated action chunk and the condition includes observations of the robot and scene.

qφ(z | target, context) → z
pθ(target | z, context)

The exact conditioning supplied to the posterior encoder and policy can differ. Original ACT’s posterior encoder uses joint state and demonstrated actions; camera features enter the policy.

08 / PUTTING IT TOGETHER

Turn observations into a chunk of actions

Action Chunking with Transformers combines a vision backbone, Transformer policy, and— in its original formulation—a conditional VAE training objective.

Why predict a whole action chunk?

Instead of predicting only the next command, ACT predicts a short sequence of future actions from the current observation. Coordinated motion can be represented across that sequence, reducing the effective decision horizon in imitation learning.

π(observationt, z) → [at, at+1, …, at+k−1]

A chunk of length k contains exactly k actions. Actions are continuous control targets, not vocabulary tokens.

For example, a 100-action chunk at 50 Hz spans 2 seconds of target commands. Those numbers are illustrative; chunk length, control frequency, and how many predicted actions are executed before replanning depend on the setup. Predicting a long chunk does not require blindly executing the whole thing.

Read the two paths

Training: the demonstration supplies the latent

  1. Joint state + expert action chunk
  2. CVAE posterior encoder
  3. μ, log σ²
  4. Sample z

The posterior encoder is a Transformer that summarizes the demonstrated action sequence and joint state. The policy then reconstructs that action chunk from observations and z. This can help represent variation in demonstrations.

Inference: use observations and z = 0

  1. Current camera images
  2. Current joint state
  3. Prior mean z = 0
  4. Policy predicts action chunk

The future expert actions are unavailable. Standard ACT inference discards the posterior encoder and sets z to the prior mean, zero. This is an inference convention for ACT; generic VAE generation usually samples z.

Project each into the Transformer’s representation width

  1. Transformer encoder fuses inputs
  2. Transformer decoder + action-position queries
  3. Linear action head
  4. k future control targets

The whole policy serves as the CVAE decoder. Inside that policy are both a Transformer encoder and a Transformer decoder. The CVAE posterior encoder is a separate training component. This is why “VAE → encoder → decoder” is too ambiguous.

What are action queries?

The Transformer decoder has output slots for the future action positions. Learned query-position embeddings identify these slots; in the original implementation, decoder target contents start at zero. Decoder self-attention relates the slots, and cross-attention lets them read the encoded observation features.

QUERY SIDE

Future action positions

Receiving representations form Q in cross-attention. Each slot corresponds to one position in the chunk.

KEY / VALUE SIDE

Encoded observations

The observation memory supplies K and V for cross-attention. The decoder uses the result to produce action features.

ACT predicts the chunk’s action positions together. It is not a GPT-style loop that samples one action token and feeds it back to generate the next. A linear head maps each decoder output to an action vector.

What does ACT learn?

LACT = L₁(predicted actions, expert actions) + β · KL(q(z | actions, state) || N(0, I))

Conceptual original objective. Padding masks and reduction conventions matter in implementations.

The reconstruction term trains accurate action predictions, while the KL term regularizes the inferred latent. The backbone, projections, Transformer layers, action queries, and action head can learn from the action error. Backbone initialization and freezing are implementation choices.

Action chunking does not mathematically require a VAE

LeRobot supports disabling the VAE component. Keep the chunked action representation separate from the optional latent-variable training objective. Neither a Transformer nor a VAE alone is synonymous with ACT.

Temporal ensembling: combine predictions for the same time

With temporal ensembling, the policy predicts overlapping chunks repeatedly. Several chunks then contain a prediction for the same actual control time. Combine those aligned predictions to produce a smoother command.

Common misconceptions, corrected

“Q, K, and V are memorized vectors stored for each word.”

The learned matrices are stored. Q/K/V are calculated from current hidden states, layer by layer. K and V may be retained in a cache for a particular generation context.

“The attention weights tell us the complete reason for the answer.”

Attention is one internal mixing mechanism. Values, projections, MLPs, residual streams, and other layers all contribute. A high attention weight alone is not a complete causal explanation.

“Backpropagation and the optimizer are the same thing.”

Backpropagation computes gradients using the chain rule. The optimizer decides how to use those gradients, potentially with momentum, adaptive scaling, and weight decay.

“All Transformer decoders generate outputs one at a time.”

Autoregressive language-model decoding does. The term Transformer decoder describes a component; ACT uses decoder output slots to predict a chunk in parallel.

“A VAE always has clean, independently controllable latent dimensions.”

The objective encourages agreement with a prior and useful reconstructions. Disentanglement and high-quality interpolation are not guaranteed.

“The robot uses future expert actions to make decisions.”

ACT’s posterior encoder uses expert actions during training. At normal inference, those actions are unavailable; the policy uses observations and a zero latent instead.
